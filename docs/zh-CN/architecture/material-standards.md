本文是[英文材质标准](../../architecture/material-standards.md)的中文摘要，覆盖消费项目最常用的材质、层级、嵌套与修复边界。具体光学数值、逐组件审计与历史验收记录以英文原文为准。

## 一种材质，三个层级

极光玻璃（Aurora Glass）是唯一的共享玻璃材质。Light / 轻薄、Standard / 标准与 Immersive / 厚实是它的层级，不是独立样式。

| 层级 | Surface | 模糊 | 背景不透明度 | 典型用途 |
| --- | --- | --- | --- | --- |
| 轻薄 | `glass-subtle` | 12px | 15% | 按钮、紧凑控件、内嵌/表单/阅读表面、应用外观 |
| 标准 | `glass-elevated` | 18px | 20% | 卡片、浮层、选择面板、终端 |
| 厚实 | `glass-immersive` | 24px | 30% | 显式厚实表面 |

`glass-*` 是稳定的技术 surface 标识，不代表另一种玻璃样式。展示名称与层级短名从 `@neoverse-ui/tokens` 的 `glassMaterial` 获取，不要自行定义。

具体数值归 `packages/tokens/src/material.css`、`effects.css` 与 `control-effects.css` 所有；组件变量是兼容别名。消费项目不需要第二套材质实现。

## 光学与主题

- 极光玻璃提供完整 CSS 基线：不透明回退、着色、背景采样、饱和度、方向性折射场、阴影与减少透明度行为。
- 浅色和深色边缘共用 `color-dodge`，按比例提亮实际底色；有条件时用饱和度通道增强其色彩。深色保留较高的曝光以维持细边可见。浅色大面的左上角与右下角在通道饱和前抑制过强的提亮，右下圆弧保留额外的饱和度增强。不支持 `color-dodge` 的浏览器继续使用叠加合成。
- 浅色大面的左上角与右下角高光按位置收窄，光照方向从直边到圆弧平滑变化。右下角向内扩展的范围比左上角窄，紧凑控件不受影响。
- 深色模式在基础曝光上限之后对左上、右下圆弧追加提亮，并在接入直边时平滑减弱至零；边缘几何与覆盖率不变。
- 边缘响应正下方像素，不采样或偏移邻近像素，因此不是空间折射。主体色调、模糊与阴影仍由 CSS 负责。
- 普通 Surface 的 `solid`、`subtle` 与 `elevated` 走 Tailwind 组合；极光玻璃只用于需要共享玻璃材质的表面。
- Surface 和 Card 的 `inset` 预设保留轻薄层级的背景模糊和柔和内阴影，不加描边，通过随主题变化的半透明底色与背景分隔。其他使用内嵌材质的控件不受影响。
- 普通和加粗的行内代码通过随主题变化的浅淡底色与正文分隔，保留柔和边缘，不加描边。代码块使用独立材质。
- 紧凑控件（按钮、复选框、单选与开关轨道）通过 `--neoverse-control-silhouette` 拥有 1px 轮廓：浅色解析为细发丝边，深色复用已验证的玻璃边缘。浅色开关滑块使用白色瓷面，避免与浅色轨道混同；玻璃平面、卡片与分段控件的边框策略保持不变。
- 复选框、单选组与开关在选中态绘制自己的蔚蓝底板：浅色保持 46% 透明度并用深蔚蓝标记，深色保持 28% 透明度并用白色标记；填充既透出底板质感，也不会依赖背景才看出选中，所有标记在底板上保持至少 3:1 的非文本对比。深色使用更深的蔚蓝并保留细亮边缘；减少透明度时切换为完全不透明的底板。
- 主按钮在浅色模式使用浅雾蓝底和深蓝文字，在深色模式使用柔和蓝底和深色文字。着色与玻璃边缘共用按钮外侧圆角，不再叠加描边。按下只加深悬停色，阴影和模糊不变；键盘焦点仍有独立轮廓。
- 导航项、分段选项、标签页、分页、菜单项与数字步进按钮使用同一套轻量底色反馈。按下比悬停深，不改阴影或尺寸；当前页、展开与选中状态独立保留。
- 分段控件（SegmentedControl）使用半透明极光玻璃外壳（保留层级背景模糊与共享 WebGL/CSS 外层玻璃边缘），内嵌延续组件库极光配色的平滑滑块，支持 `pill`（默认）与 `rounded` 形态（`shape`），并与 `ControlSurface`、`Tabs`、`Pagination` 及 `NavigationItem` 的几何与选中变量解耦；滑块与文字颜色以 320ms 柔和弹簧曲线平滑切换并带轻度按压缩放反馈，在减少动效时立即切换。
- Badge 保留轻薄层级的背景模糊、细描边和内侧高光，不加外部光晕，避免 Chromium 重绘时在圆角端部闪出深色条带。
- TooltipSurface 的中性样式用淡蓝色，强调样式用更浓的主题强调色。两种样式的主体与箭头在纯色背景上仍可辨认，均保留轻薄层级的填充透明度、背景模糊和共享玻璃边缘。减少透明度时保留着色，改用不透明底色。
- 中性 Notice 用随主题变化的浅淡底色与纯色背景分隔，保留轻薄层级的填充透明度、背景模糊和内阴影，不加描边。其他状态样式的语义色不变。
- Skeleton 占位面保留共享高光与 pulse，不再叠加顶部深色边缘；pulse 示例只播放 pulse，不生成 shimmer 扫光。
- 导航表面只拥有一个强调色：改了选中底板的表面，必须用同一强调色同时改左侧竖条与底部横条；朝向别名在条目上解析，而不是在文档根上解析。库默认把薄荷色选中底板与薄荷色指示条配成一对，因此只有替换了底板的表面才需要声明自己的强调色。
- 面包屑链接改用普通链接的反馈：链接用底板内距扩大自身盒子，再用等量负外边距把空间还给轨迹；容器也带上同一内距，使内距范围内都可命中，同时路径几何不变。底板填满该盒子，使用共享 hover 场，淡入时由略小放大，按下再叠加加深，文字同时提升到主文本层级——强调色文字落在强调色底板上，在浅色模式下会低于 3:1。容器使用 `overflow-clip-margin` 裁切，不再使用会切掉底板与焦点轮廓的 `overflow: hidden`。

## 嵌套

- 独立极光玻璃表面必须在 hover 之前就渲染自己的着色、边框、背景滤镜与阴影，包括嵌套在极光玻璃布局内部时。
- Vue 与 React 的 `UiSurface` 默认 `glassNesting="local"`；`UiCard` 也保留自己的材质，不需要嵌套覆盖。
- 只有确实借用父级极光玻璃平面的布局分组才设置 `glassNesting="inherit"`（Vue：`glass-nesting="inherit"`）。
- 有意不使用材质的组件设置 `surface="none"`，不要依赖全局规则压平所有未标记的嵌套表面。
- 导航项的持久选中底板属于组件自有平面，而不是临时的 Ghost 反馈；即使交互表面为 `surface="none"`，选中态仍采样背景，hover 与 press 仍只绘制局部洗色。

## 减少透明度与强制颜色

透明度效果不可用或用户偏好减少透明度时，表面必须保持可读。CSS 回退使用仅含 alpha 的渐变遮罩与背景亮度；减少透明度会禁用可选渲染器。强制颜色模式下，原生控件与系统颜色语义优先，材质不得覆盖可见焦点或文本对比。

## Glass 修复守则

1. 不要为了修复边缘外观而把默认渲染器切换为全表面 SVG 背景位移，不要添加背景捕获/重建层，也不要替换层级负责的主体模糊。这些方案曾多次造成严重卡顿、模糊丢失或边缘缺失。
2. 保持整个边缘可见且细致；强调左上与右下，但不要移除其他边或角。
3. 同时验证背景相关颜色、真实模糊、边缘连续性与性能；不要用主题色叠加描述为真实空间折射。
4. 建议的轻量路径 `suspend()` / `resume()` 只适用于整页位置与不透明度过渡。尺寸、层叠顺序或顶层变化仍需完整刷新；不要跨缩放表面或打开浮层的过渡执行暂停。
5. 浅色/深色、减少动效、减少透明度、强制颜色、桌面与移动宽度都需要检查。像素差值光学套件只是回归诊断信号，不能替代人工渲染验收。

## 验证

- 运行时单测覆盖 WebGL 选择、上下文丢失与恢复、共享画布复用、帧调度与减少透明度切换。
- Chromium 集成测试检查保留的 CSS 模糊、渲染器所有权与无 WebGL 回退。
- Linux Chromium + SwiftShader 套件记录亮/暗像素差值，用于边缘连续性、角部响应与内部泄漏诊断。
- 最终外观、实时背景行为与性能仍需人工验收。完整的逐组件审计、光学数值与历史记录见[英文材质标准](../../architecture/material-standards.md)。
