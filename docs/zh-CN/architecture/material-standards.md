本文是[英文材质标准](../../architecture/material-standards.md)的中文摘要，覆盖消费项目最常用的材质、层级、嵌套与修复边界。具体光学数值、逐组件审计与历史验收记录以英文原文为准。

## 共享材质解析

`@neoverse-ui/tokens` 定义 `Material`（材质）、`SurfaceRole`（表面角色）与 `GlassTier`（极光玻璃光学层级）。表面角色表达组件职责；表面配方决定该角色在给定材质中的绘制。Theme 独立控制主题颜色。

在文档根、子树或表面自身设置 `data-neoverse-material`，取最近的有效值：`solid`、`frosted` 或 `glass`。未知值不阻断父级作用域，无有效值时默认极光玻璃。CSS 在框架挂载前解析作用域。显式 `surface` 只覆盖当前表面，不影响后代作用域；`none` 不绘制底板，`frosted` 为当前表面角色选择磨砂配方，原有 `inset` 仍保留轻薄层级采样。

两套适配器输出相同的自动表面角色，不再附加具体材质类。Tailwind 通过对称的 `@scope` 边界（`solid`、`frosted`、`glass`）匹配配方；只有具备光学资格的极光玻璃表面会向可选渲染器宣告层级。浏览器顶层不改变 DOM 作用域；Dialog、模态 Drawer、Toast 与 ContextMenu 的 Portal 在退出动画挂载期间仍同步调用位置的作用域。

迁移时以 `Material` 替换 `MaterialMode`，以 `SurfaceRole` 替换 `MaterialSurfaceRole`；使用 `getSurfaceClass(selection, role)` 替代旧的预设映射。不要再用自动标记上的 `material-auto`、`material-solid-*` 或 `material-glass-*` 推断材质。

## 三材质设计规范

不透明材质（Solid）、磨砂材质（Frosted）与极光玻璃（Aurora Glass）地位平等，共享品牌色、排版、圆角、间距、组件密度、交互语义与动效角色，同时各自保持独立的表面语言：

| 材质 | 核心特征 | 渲染机制 | Glass Runtime |
| --- | --- | --- | --- |
| 不透明材质（Solid） | 实体、清晰、低背景依赖、色阶与轻阴影分层 | 原生 CSS | 不启用 |
| 磨砂材质（Frosted） | 半透明、柔和漫反射、克制边缘与空间层次 | 原生 CSS `backdrop-filter` | 不启用 |
| 极光玻璃（Aurora Glass） | 光学透明感、方向性边缘高光、三层级深度 | CSS + 可选 Glass Runtime | 仅合格极光玻璃表面 |

基础数值由 `packages/tokens/src/materials/glass.css`（极光玻璃）、`packages/tokens/src/materials/solid.css`（不透明状态底板）、`packages/tokens/src/materials/frosted.css`（磨砂尺度与各角色配方）及 `packages/tokens/src/themes/{light,dark}.css` 定义。极光玻璃的光学参数不进入其他两种材质的样式变量。

## 材质运行时与切换

Playground、Frame 路由与 React 测试页面共用一个框架无关的材质模块。保存的 `material` 偏好在首绘启动脚本中写入 `data-neoverse-material`，首帧即使用所选材质。`?material=` 只是同一策略下的临时预览，不写入偏好；刷新保留最后一次交互选择。材质与 Theme、Locale、舞台背景和展示表面相互独立，属性仍是唯一生效规范。

工具栏在桌面用分段控件、在触屏用循环按钮提供极光玻璃、实体与磨砂三种平级选项。显式表面仍优先于全局材质；切换不重置样例会话、表单值、选中项、焦点、滚动位置与 Stage 缩放。

切换使用外观快照（`material-fade`），不逐帧插值模糊、折射或阴影。减少动效与不支持 View Transition API 的浏览器立即切换。连续快速请求以最后一次为准：被取消的快照只绘制最新选择，切换结束后不残留光学边缘、浮层闪烁或布局跳变。

## 磨砂材质

磨砂材质是独立的半透明表面方案，基于原生 CSS `backdrop-filter`、较高表面不透明度、克制的饱和度、1px 柔和哑光边缘与平静的环境阴影。它不是简单叠加模糊的实体材质，也不是关闭折射后的极光玻璃：不使用极光玻璃层级、方向性光学边缘、色散或任何 JavaScript 运行时。

`cssVariables.material.frosted` 提供主题底色、哑光边框、阴影、交互洗色、选中与主色底板、遮罩以及各角色的模糊/饱和度/不透明度尺度：

| 表面角色 | 独立模糊 | 饱和度 | 填充不透明度 | 嵌套行为 |
| --- | --- | --- | --- | --- |
| `panel` | 16px | 118% | 76% | 跳过模糊（`none`），切换为 `panel-nested-fill` 与更轻阴影 |
| `overlay` | 20px | 124% | 82%（`dialog` 为 86%） | 始终独立采样（独立浮层空间） |
| `compactOverlay` | 14px | 118% | 84% | 始终独立采样 |
| `group` | 12px | 112% | 68% | 跳过模糊（`none`），切换为 `group-nested-fill` |
| `control` | 10px | 112% | 74% | 跳过模糊（`none`），切换为 `control-nested-fill`；无填充按钮保持透明 |
| `table` | 14px | 118% | 78% | 仅在 `<table>` 采样一次，单元格不单独执行背景模糊 |
| `field` | 8px | 112% | 80% | 跳过模糊（`none`），切换为 `field-nested-fill` |

紧凑控件（`UiBadge`、`UiChoice`、`UiSkeleton`、分段/标签/分页选中指示块、行内 `code`/`kbd`）始终保持 `backdrop-filter: none`，避免密集界面生成多余合成层；`UiNotice` 仅在独立放置时采样背景。

磨砂配方默认先绘制完全不透明的主题回退色（`--neoverse-material-frosted-base*`），仅在 `@supports` 确认支持 `backdrop-filter` 与 `color-mix()` 后才启用半透明填充与背景模糊。开启 `prefers-reduced-transparency: reduce` 时平滑退回完全不透明底色并关闭模糊，且不修改保存的材质偏好，也不重置输入状态；开启 `forced-colors: active` 时完全交由系统配色呈现。所有降级均通过 CSS 能力检测完成，不依赖 User-Agent 判断。

## 实体材质

实体材质不等同于极光玻璃的减少透明度模式。`cssVariables.material.solid` 提供 Canvas、Control、Group、Raised、嵌套面板阶梯（`raised-nested`、`nested-shadow`）、分组内控件抬升（`control-in-group`）、Inset、Overlay、Compact Overlay、禁用底板、主/语义按钮填充色与 Selection 角色。浅色使用淡蓝中性色阶，深色使用近黑至蓝灰色阶；主按钮使用蓝色，选中底板在浅色使用浅蓝、深色使用深蔚蓝与 Raised 面混合的柔和蔚蓝，两种材质均以主文字色作为选中文字；选中指示线保留强调色。状态徽章在实体模式下保留语义色相：深色底用明亮状态色，浅色底用深色状态色；中性徽章与 Notice 文字在两种材质下都使用次要文字色，并在两种模式下保持可读。应用自行选择是否在页面背景使用 Canvas。

- 控件保留焦点和校验反馈；复选框、单选和开关的选中底板复用主色及配对前景。分段滑块、导航指示器和分页保留原有动效。
- Tabs 省略 `variant` 时采用自动材质；显式 `variant="glass"` 保留极光玻璃。`underline` 仍只绘制指示线，`pill` 跟随作用域。
- 浮层采用 Overlay，模态浮层另绘遮罩。提示框箭头与主体同色。状态面和占位面使用不透明色阶，不依赖模糊或光晕。
- 终端的外壳、标题栏和正文采用分组色阶，提示符、回显、行和记录不叠加底板。Prose 的表格与折叠块共享组件配方；引用和代码块使用 Inset，行内代码和按键使用 Group。

在 Design Lab 或 React 测试页面的原有地址上加 `?material=glass`、`?material=frosted` 或 `?material=solid`，并与 `theme=light` 或 `theme=dark` 组合查看。该参数只作用于预览，不持久化偏好，也不覆盖显式预设。

## 嵌套材质与背景采样所有权

- 三种材质支持任意父子嵌套与局部覆盖，对称 `@scope` 边界防止样式变量、滤镜、阴影与伪元素跨材质泄漏。
- 实体材质中，嵌套面板切换至 `raised-nested` 与更轻阴影，位于 `group` 内的控件抬升至 `control-in-group`。
- 磨砂材质中，磨砂采样平面（`panel`、`group`、`overlay`、`compactOverlay`）的后代自动跳过二次背景模糊并切换至嵌套色阶，避免双重模糊浑浊与合成层膨胀；独立浮层（`overlay`、`compactOverlay`）、新的材质作用域边界（`[data-neoverse-material]`）与显式极光玻璃表面会重置嵌套变量，保持独立采样。
- 极光玻璃的 WebGL 表单/表格阴影覆写严格限定在极光玻璃作用域内，同一页面混用显式极光玻璃表面时不会影响实体或磨砂控件。

## 极光玻璃的三个层级

极光玻璃（Aurora Glass）是唯一的共享玻璃材质。Light / 轻薄、Standard / 标准与 Immersive / 厚实是它的层级，不是独立样式。

| 层级 | Surface | 模糊 | 背景不透明度 | 典型用途 |
| --- | --- | --- | --- | --- |
| 轻薄 | `glass-subtle` | 12px | 15% | 按钮、紧凑控件、内嵌/表单/阅读表面、应用外观 |
| 标准 | `glass-elevated` | 18px | 20% | 卡片、浮层、选择面板、终端 |
| 厚实 | `glass-immersive` | 24px | 30% | 显式厚实表面 |

`glass-*` 是稳定的技术 surface 标识，不代表另一种玻璃样式。展示名称与层级短名从 `@neoverse-ui/tokens` 的 `glassMaterial` 获取，不要自行定义。

具体数值归 `packages/tokens/src/materials/glass.css`、`packages/tokens/src/semantic/effects.css` 与 `packages/tokens/src/semantic/control-effects.css` 所有；组件变量是兼容别名。消费项目不需要第二套材质实现。

## 光学与主题

- 极光玻璃提供完整 CSS 基线：不透明回退、着色、背景采样、饱和度、方向性折射场、阴影与减少透明度行为。
- 浅色和深色边缘共用 `color-dodge`，按比例提亮实际底色。只有浅色额外增强底色饱和度，深色保留较高曝光以维持细边可见，但不额外放大底色中的蓝色。不支持 `color-dodge` 的浏览器继续使用叠加合成；深色各通道的增益相同。
- 左上角与右下角采用同一条提亮曲线，实际亮度仍随底色变化。浅色大面的两个高光向内收窄的幅度一致，并在通道饱和前抑制过强的提亮；大面的右下圆弧额外增强饱和度。
- 深色模式在卡片与控件间共用适中的对角高光集中度（`0.5`），既保留直边连续细边，也让卡片与大表面显现左上、右下高光。深色高光的面积提亮、向内衰减与覆盖上限随表面短边尺寸缩放：按钮等紧凑控件与圆形图标按钮保持克制，防止高亮度填充过曝；卡片与较大表面将左上、右下高光平滑延伸至相邻直边端部（按短边设上限），直边中段与外轮廓保持细腻连续。
- [深色宽卡片基线](../../architecture/material-standards.md#dark-wide-surface-baseline)覆盖三个玻璃层级：两个高光必须延伸到相邻直边端部，四边与另外两角连续可见，主体模糊不变；浅色与深色高光方向一致，不要求绝对亮度与颜色相同。光学套件同时校验深色紧凑主按钮的细边连续性与高光亮度上限，回归阈值由光学用例维护，不固定逐像素截图。
- 边缘响应正下方像素，不采样或偏移邻近像素，因此不是空间折射。主体色调、模糊与阴影仍由 CSS 负责。
- 画布与 CSS 回退都以组件外边界为基准。轴向放大时，圆角按实际 CSS 缩放计算，饱和度描边随宽度向内收，避免越出圆角。
- 普通 Surface 的 `solid`、`subtle` 与 `elevated` 走 Tailwind 组合；极光玻璃只用于需要共享玻璃材质的表面。
- Surface 和 Card 的 `inset` 预设保留轻薄层级的背景模糊和柔和内阴影，不加描边，通过随主题变化的半透明底色与背景分隔。其他使用内嵌材质的控件不受影响。正文引用块复用同一底色角色，因此读起来是独立表面，而不是一层裸玻璃色调。
- 普通和加粗的行内代码通过随主题变化的浅淡底色与正文分隔，保留柔和边缘，不加描边。代码块使用独立材质。
- 紧凑控件（按钮、复选框、单选与开关轨道）通过 `--neoverse-control-silhouette` 拥有 1px 轮廓：浅色解析为细发丝边，深色复用已验证的玻璃边缘。浅色开关滑块使用白色瓷面，避免与浅色轨道混同；玻璃平面、卡片与分段控件的边框策略保持不变。
- 复选框、单选组与开关在选中态绘制自己的蔚蓝底板：浅色保持 46% 透明度并用深蔚蓝标记，深色保持 28% 透明度并用白色标记；填充既透出底板质感，也不会依赖背景才看出选中，所有标记在底板上保持至少 3:1 的非文本对比。深色使用更深的蔚蓝并保留细亮边缘；减少透明度时切换为完全不透明的底板。
- 主按钮在浅色和深色模式都使用半透明蓝色，分别搭配深蓝和近黑文字。有底板的 Button、Action、IconButton 和浮层触发按钮直接在组件外边界内绘制底色与交互反馈。按下只加深悬停色，阴影和模糊不变。CSS 回退只裁切边缘层，不裁切键盘焦点环或扩大的触控热区。
- 键盘焦点环在浅色与深色模式下均由主强调色（蓝色 `--neoverse-color-focus-ring`）派生，包括蓝色按钮、输入框、分段控件与处于选中态的导航项。
- 导航项（未选中态）、分段选项（未选中态）、标签页（未选中态）、分页（未选中态）、菜单项、Toast 关闭按钮与数字步进按钮使用同一套轻量底色反馈（`--neoverse-quiet-control-feedback`），统一悬停与按下过渡，不改阴影或尺寸；当前页、展开与选中状态独立保留。已选中的分段滑块、标签页、分页与导航项底板在悬停和按下时直接切换至与主按钮一致的选中态悬停/按下蓝色反馈（`--neoverse-effect-choice-selected-hover-*` / `-press-*`，深色模式下像素对齐主按钮，浅色模式下沿主按钮同色系提亮增透），不再在激活底板上叠加灰雾洗色。菜单与 Select 选中项使用中性冷灰底纹搭配主文本色。
- 分段控件（SegmentedControl）的半透明极光玻璃外壳保留层级背景模糊和共享 WebGL/CSS 外层玻璃边缘；内部滑块与选中底板采用无描边的半透明冰蓝磨砂（浅色为晴空冰蓝、深色与主要按钮天空蓝一致并搭配深色文字 `--neoverse-effect-choice-selected-foreground`）和轻薄层级 `12px` 背景模糊（`--neoverse-control-segmented-active-filter`），且浅深色均不绘制顶部白色内描边和多余外阴影（`--neoverse-control-segmented-active-shadow`），渐变使用 `border-box` 原点与 `no-repeat` 避免透明边框边缘裁切感，并保留滑块轨道留白以消除亚像素裁切。按下时滑块向目标滑动并短暂拉伸，按住保持收缩：胶囊形态纵向上压扁，圆形（如图标模式与等宽高选项）及 `rounded` 形态以中心等比缩小；横向拖动时跟随指针，释放后选中最近的可用项。取消或拒绝选择时回到已选项，触屏仍可纵向滚动。减少动效时保留直接拖动，不播放预览和回弹。Vue 与 React 均支持 `variant="text"`（默认，按文字宽度）、`variant="icon"`（等宽图标选项）和 `variant="language"`（等宽紧凑语言标签）。图标由 `options[].icon` 提供，`label` 为选项命名，也在缺少图标时作为可见文字，`ariaLabel` 可补充完整名称。
- 悬停于已选项、按下或拖动时，滑块与指示底板直接随同切换至与主按钮对齐的选中态悬停/按下反馈，并在拖动/按住期间保持同色系薄釉层（`--segment-feedback`），不在选项下另绘灰雾层。
- Badge 保留轻薄层级的背景模糊、细描边和内侧高光，不加外部光晕，避免 Chromium 重绘时在圆角端部闪出深色条带。
- TooltipSurface 的中性样式用淡蓝色，强调样式用更浓的主题强调色。两种样式的主体与箭头在纯色背景上仍可辨认，均保留轻薄层级的填充透明度、背景模糊和共享玻璃边缘。减少透明度时保留着色，改用不透明底色。
- 中性 Notice 用随主题变化的浅淡底色与纯色背景分隔，保留轻薄层级的填充透明度、背景模糊和内阴影，不加描边。其他状态样式的语义色不变。
- Toast 的三种布局共用标准层级的极光玻璃，并统一在右上角以同级标准层级材质层骑跨定位相同的圆形关闭徽章按钮（由 `--neoverse-toast-dismiss-*` 样式变量控制，块起边与行尾边均偏移 `-size / 3`），同时在右侧为内容预留避让内边距。将正文面层与关闭按钮保持为同级材质层，可以让两者各自生效背景模糊，并让共享边缘渲染器在圆形按钮下方遮罩裁切 Toast 的转角边缘。`compact` 是包含语义图标与短文案的单行胶囊；`action` 是将行内操作置于文案右侧的圆角条；`notification` 支持多行文案并将操作放在文案下方。前两种默认四秒后自动关闭，也可以随时提前手动关闭；`notification` 与 `duration` 为零时保持打开。
- Skeleton 占位面保留共享高光与 pulse，不再叠加顶部深色边缘；pulse 示例只播放 pulse，不生成 shimmer 扫光。
- 导航表面只拥有一个强调色：改了指示条的表面，必须用同一强调色同时改左侧竖条与底部横条；朝向别名在条目上解析，而不是在文档根上解析。浅色把冰蓝透明选中底板与主色蔚蓝指示条（`--neoverse-color-accent-primary`）配成一对；深色把深海军蓝选中底板（`--neoverse-navigation-item-active-fill`）与浅天蓝指示条（`--neoverse-color-blue-300`）配成一对，使指示条在底板与深色背景上都保持分离度。
- 面包屑链接改用普通链接的反馈：链接用底板内距扩大自身盒子，再用等量负外边距把空间还给轨迹；容器也带上同一内距，使内距范围内都可命中，同时路径几何不变。底板填满该盒子，使用共享 hover 场，淡入时由略小放大，按下再叠加加深，文字同时提升到主文本层级——强调色文字落在强调色底板上，在浅色模式下会低于 3:1。容器使用 `overflow-clip-margin` 裁切，不再使用会切掉底板与焦点轮廓的 `overflow: hidden`。

## 嵌套

- 独立极光玻璃表面必须在 hover 之前就渲染自己的着色、边框、背景滤镜与阴影，包括嵌套在极光玻璃布局内部时。
- Vue 与 React 的 `UiSurface` 默认 `glassNesting="local"`；`UiCard` 也保留自己的材质，不需要嵌套覆盖。
- 只有确实借用父级极光玻璃平面的布局分组才设置 `glassNesting="inherit"`（Vue：`glass-nesting="inherit"`）。
- 有意不使用材质的组件设置 `surface="none"`，不要依赖全局规则压平所有未标记的嵌套表面。
- 导航项的持久选中底板属于组件自有平面，而不是临时的 Ghost 反馈；即使交互表面为 `surface="none"`，选中态仍采样背景，hover 与 press 仍只绘制局部洗色。

## 减少透明度与强制颜色

透明度效果不可用或用户偏好减少透明度时，表面必须保持可读。CSS 回退使用仅含 alpha 的渐变遮罩与背景亮度；减少透明度会禁用可选渲染器。强制颜色模式下，原生控件与系统颜色语义优先，材质不得覆盖可见焦点或文本对比。

渲染器仅在存在可绘制的合格光学表面时激活。纯实体与纯磨砂页面不创建画布、WebGL 上下文、Shader Program 或 Buffer。最后一个合格表面消失后会释放上下文、原生 SVG 滤镜与缓存映射，整页过渡先暂停时除外。

## Glass 修复守则

1. 不要为了修复边缘外观而把默认渲染器切换为全表面 SVG 背景位移，不要添加背景捕获/重建层，也不要替换层级负责的主体模糊。这些方案曾多次造成严重卡顿、模糊丢失或边缘缺失。
2. 保持整个边缘可见且细致；强调左上与右下，但不要移除其他边或角。
3. 同时验证背景相关颜色、真实模糊、边缘连续性与性能；不要用主题色叠加描述为真实空间折射。
4. 建议的轻量路径 `suspend()` / `resume()` 只适用于整页位置与不透明度过渡。尺寸、层叠顺序或顶层变化仍需完整刷新；不要跨缩放表面或打开浮层的过渡执行暂停。
5. 浅色/深色、减少动效、减少透明度、强制颜色、桌面与移动宽度都需要检查。像素差值光学套件只是回归诊断信号，不能替代人工渲染验收。
